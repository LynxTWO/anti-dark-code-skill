# Repository verification profiles

Use the runtime branches needed to interpret a selected capability or unresolved disposition under [Verify](tasks/verify.md). Apply [core evidence and authority](../SKILL.md). The [machine catalog](../assets/verification-capabilities.json) owns IDs, statuses, default levels and detailed adaptations. Profiles are evidence-based suggestions, not permission to install or run tools.

| Runtime shape | Priorities and domain adaptations |
|---|---|
| Service/web backend | Transaction/auth/idempotency invariants and boundary contracts; transport/domain/persistence/privileged-job architecture; event replay, hermetic service substitutes and latency/queue/connection/memory budgets. Model account/order/deletion/permission sequences. Compare API/adapter migrations; test valid retry, pagination, ordering and batching relations. Inject dependency/partial-write faults only under applicable isolation and authority. |
| Frontend/browser | Stateful navigation plus random exploration; state-store invariants; API/storage/route/flag contracts; semantic DOM/view-model/screenshot goldens; render/bundle/listener/detached-node/long-session budgets. Exercise offline, quota, suspension, stale cache and slow network. Keep UI outside private domain/persistence layers. Review broad mocks and baseline changes. Fresh nested selector objects need identity/render-count guards where they can loop. |
| Monorepo | Package/layer ownership, semantic change impact, hermetic package/cache inputs, runtime maps and per-package ladders/logs under a compact root verdict. Compare shared-library migrations; focus mutation/property checks on affected risky packages. One package cannot establish whole-repo coverage; sibling repos and vendor planes retain separate obligations. |
| Library/SDK | Public API/serialization/compatibility contracts, reference-versus-optimized differential checks, public-behavior mutation and algebraic relations, version/platform matrices and semantic API/artifact goldens. Separate public interfaces from internals. Include downstream examples/generated clients and compatibility cases in impact; reject silent re-recording. |
| Game/simulation | Explicit seed/time/RNG/IDs/locale/content identity; save/start state/actions/receipts for replay; stateful/adversarial and random exploration; impossible-state/economy invariants; chunking/order/scaling/resistance/conservation/round-trip relations; save/map/content goldens; frame/tick/resource budgets and interruption/asset/worker/storage faults. Keep diagnostics observational and projections tied to canonical rules. Retain a fixed-input aggregate action/economy/difficulty/population canary; isolate regressions by counts, baseline diff and one config at a time. |
| Mobile/native | Permission/lifecycle/navigation/offline/background state models and replay; bridge/storage/push/deep-link/platform contracts; device/OS/locale/toolchain isolation; interruption, low-storage, kill, denial and network-change faults; startup/frame/battery/memory/bridge budgets. Guard secure-storage and bridge access. Compare platform adapters; put full device matrices at the measured broad-check level, while reporting every unsupported tuple. |
| Infrastructure | Module/variable/policy/state contracts; IAM/environment/runner boundaries; intended/prior-plan differential checks; module/environment impact; pinned providers and isolated state; semantic plan/policy goldens and disposable-sandbox faults. Plan evidence does not authorize apply or prove remote state. Redact sensitive account/address data; scrutinize suppressions and widened policy exceptions. |
| AI/data | Data/feature/prompt/tool/output contracts; old/new pipeline/model/route comparisons; valid row-order/batch/partition/scaling/paraphrase relations; pinned data/model/locale/environment identity; eval/output/report/lineage goldens; cost/latency/memory/throughput/drift budgets; malformed/missing-data/service/backfill faults. Separate deterministic correctness from probabilistic quality. Replay identity includes model, prompt, tool schema, dataset and route versions; never obtain it by leaking sensitive prompts. |
| CLI/desktop | Command/file/config/IPC/exit contracts; workflow models and replay; isolated temp/home/locale/terminal/OS inputs; semantic stdout/file/migration/UI goldens; permissions/locks/full-disk/interruption/child faults and startup/handle/memory budgets. Preserve actual exits and redacted argv; test shell behavior per platform and legacy-format adapters. |
| Small/new | Start with real invariants, boundary schemas, an exact useful gate, compact map, test-change review and failure packets. Add measured ladder levels and other capabilities only when observed behavior and risk justify them. Do not invent missing product paths. |

Cross-profile rules: mutation needs meaningful tests; differential testing needs an independent implementation/oracle; time/randomness/ordering call for explicit replay inputs. Change impact includes configuration, content, generated, schema and deployment/control-plane edges. Snapshots require semantic review. Fault injection stays isolated and authorized. Builder/challenger separation scales to stakes; a model vote cannot replace a deterministic oracle.
