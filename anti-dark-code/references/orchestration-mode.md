# Optional orchestration

Load when independent work and consequential claims justify delegation, and the active host/user instructions permit it. It does not add a mandatory audit stage. Task acceptance and the [core contract](../SKILL.md) apply unchanged.

## Divide work by evidence obligation

Use deterministic tools for enumeration, counts, hashes, citation checks, diffs and command status. Delegate bounded interpretation or challenge with required inputs, owned scope, evidence obligations, stop conditions and a compact output contract. Select claims by stakes and falsifiability, not a fixed number of agents per task. Missing subagents means inline work.

Slice mixed repositories by runtime unit before specialist lens: services, native bridges, storage, deployment, pipelines, release tooling, saved prose or authoritative state. Load [adversarial guidance](07-adversarial-review.md) for concrete risks. Infrastructure apply, native runtime access and production systems keep their existing authority boundaries.

Before fan-out identify agent count and available model/effort choices within the user's budget. [Host adapters](host-adapters.md) describe available controls; do not assume inherited defaults or unavailable knobs. Keep builder and challenger responsibilities separate for consequential changes. A verifier never edits what it grades.

## Protect shared state

Assign non-overlapping write ownership before launching agents. The orchestrator owns shared deliverables and integration. Serialize formatters, generators, cleanup, restores, builds and producers/consumers sharing mutable outputs. Inspect the complete worktree diff after fan-out; agent reports are not an exhaustive change inventory.

Run independent authorized deterministic gates alongside analysis only when outputs are disjoint. Review exact commands before executing repository code. Capture real child exit status, source identity and evidence scope; a successful pipeline consumer does not establish producer success. Stop expensive dependent work after a cheap blocking failure unless another check answers a named diagnostic question.

Use selected [verification-plan](14-deterministic-verification.md) capabilities and bounded failure packets. Green logs need compact summaries, not repeated model narration.

## Challenge and integrate

Claims returned by agents begin inferred with run/agent/source provenance. Promote a source fact only after authenticated evidence is reopened and supports it; promote observed behavior only with an authorized recorded observation of the claimed scope. Two agreeing agents do not establish verification.

Personally check every top-risk citation and sample at least one per lower-risk agent. A failed sample leaves that agent's report inferred pending recheck. Keep claim kind, confidence and coverage disposition separate. Record unexamined overflow as deferred/blocked coverage, not a new confidence label.

For supported consequential findings, use a challenger to refute the claim or trace the concrete trigger independently. Give it the claim and relevant evidence without requiring agreement with the finder's narrative. Uncertainty means unresolved, not automatically refuted. Deterministic reproduction settles reproducible behavior; scope limitations stay attached.

Reject names, versions, owners and product claims imported from ambient host context without repository evidence.

## Checkpoints and recovery

After completed evidence units and before long operations, save task/scope, source identity, evidence locators, remaining coverage, authorization limits and next action in existing authorized records. Reuse preserved outputs only after checking identity, freshness and relevant invalidation dependencies. Reinspect uncertain or in-flight work before retrying it; do not blindly repeat side effects.

Run IDs and cache recovery are optional host facilities, not universal billing guarantees. Count paid retries and revalidation in actual usage. At checkpoints, distinguish misunderstanding from incomplete coverage before changing available model/effort settings; record the evidence and decision. No failure signal needs no escalation. Do not interrupt healthy work merely to retrofit a scheduling improvement.

Use process/journal tools to monitor progress. Distill scratch results into durable evidence; [cleanup](09-artifact-gc.md) remains subject to its separate scope and recovery rules.

Completion requires the task's outputs, provenance-supported confidence, explicit omitted coverage, integrated diff review and a usable recovery checkpoint when work remains. Model agreement and a handoff summary never replace evidence.
